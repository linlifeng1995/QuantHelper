# MyQuant 项目设计文档

更新时间：2026-05-28

## 1. 项目定位

MyQuant 是一个面向 A 股研究与交易前检查的本地量化工作台。项目当前同时保留旧版 Streamlit 原型和新版 Next.js + FastAPI 工作台：

- 通过 Tushare/TeaJoin 拉取行情、估值、财务指标等数据，并缓存到本地。
- 基于价格、估值、质量、成长、风险等因子做股票筛选。
- 支持观察池/股票池管理、个股详情、择时状态、交易计划、风控检查和场景模拟。
- 支持固定股票池回测、价格滚动回测、历史回测记录。
- 提供 Agent 助手，对个股、筛选结果、回测和新闻做研究性解释。

项目定位是“研究辅助与交易前检查”，不是自动交易系统。所有策略、计划、Agent 输出都应被视作研究参考，需要人工复核数据质量、交易可执行性和风险。

## 2. 技术栈

| 层级 | 技术 | 说明 |
| --- | --- | --- |
| 前端 | Next.js 16、React 19、TypeScript、Ant Design、ECharts | 新版主工作台 |
| 后端 API | FastAPI、Pydantic、Uvicorn | 对前端提供 REST 接口 |
| 量化计算 | pandas、numpy | 行情矩阵、因子、回测、指标计算 |
| 存储 | SQLite + SQLAlchemy、pickle、parquet、JSON | 新模块使用 SQLite；历史缓存仍保留文件格式 |
| 旧版原型 | Streamlit | 保留为对照和数据能力底座 |
| 外部数据 | Tushare/TeaJoin、Google News RSS | 行情/基础面/新闻来源 |
| Agent | Kimi、DeepSeek OpenAI-compatible API | 研究解释与辅助分析 |

当前代码演进形态是“旧能力底座 + 新模块渐进替换”：

- `web_app.py` 仍承载大量成熟函数，例如缓存读写、Tushare 下载、旧版因子筛选、固定股票池回测。
- `myquant/` 正在把领域能力拆成清晰模块，例如 `factors`、`screening`、`planning`、`risk`、`backtest`、`agents`。
- `api/main.py` 仍包含一批兼容旧前端/旧流程的端点，同时挂载 `api/routers/` 下的新路由。

## 5. 后端入口设计

### 5.1 FastAPI 应用

入口：`api/main.py`

职责：

- 创建 FastAPI 应用，配置 CORS。
- 启动时执行数据库建表、默认股票池、旧观察池迁移、因子注册表、风控默认值初始化。
- 挂载模块化路由：
  - `/api/pools`
  - `/api/factors`
  - `/api/screen`
  - `/api/risk`
  - `/api/timing`
  - `/api/plans`
  - `/api/recommend`
  - `/api/stock`
  - `/api/snapshots`
  - `/api/backtest`
  - `/api/scenario`
  - `/api/agent`
- 保留旧版兼容端点：
  - `/api/cache/summary`
  - `/api/tasks`
  - `/api/watchlist`
  - `/api/screen`
  - `/api/backtest`
  - `/api/backtest/rolling` 占位接口

### 5.2 后台任务

数据更新任务在 FastAPI 进程内通过线程执行，状态保存在内存字典 `TASKS`：

- `sync_latest`：同步到最新交易日。
- `repair_price`：补齐缺失或落后的行情缓存。
- `refresh_fundamentals`：刷新 ROE/GROWTH 等基础面字段。
- `rebuild_price`：高级全量重建价格缓存。

约束：

- 同一时间只允许一个数据更新任务执行。
- 支持取消，但取消点依赖当前下载批次结束。
- 任务历史仅保存在当前 FastAPI 进程内，重启后丢失。

## 6. 领域模块设计

### 6.1 数据与缓存

核心文件：

- `web_app.py`
- `myquant/data/snapshots.py`
- `myquant/tushare_client.py`
- `myquant/config.py`

主要缓存：

| 文件/表 | 用途 |
| --- | --- |
| `outputs/cache/price_cache.pkl` | 历史收盘价矩阵，index 为交易日，columns 为 ticker/指数列 |
| `outputs/cache/pool_cache.pkl` | 股票池快照，包含名称、行业、估值、财务、成交额等字段 |
| `outputs/cache/watchlist.json` | 旧观察池文件，仍由旧兼容接口使用 |
| `outputs/cache/myquant.db` | 新版 SQLite 主数据库 |
| `outputs/cache/ohlcv/*.parquet` | 单标的 K 线 OHLCV 缓存 |
| `outputs/*.csv` | 选股、回测等导出结果 |

数据设计原则：

- 价格缓存用于高频读取，采用矩阵格式便于 pandas 计算。
- 股票池缓存保留宽表形态，兼容旧筛选逻辑和前端展示。
- 新增业务状态逐步迁移到 SQLite，例如股票池、交易计划、风控设置、回测记录、基础面快照。
- 财务快照使用 `ann_date` 作为防未来函数关键字段，只有公告日不晚于评估日的数据才可进入历史评估。

### 6.2 数据快照

核心文件：`myquant/data/snapshots.py`

支持两类快照：

- `DailyBasicSnapshot`：每日估值/市值/换手等切片，来自 Tushare `daily_basic`。
- `FinaSnapshot`：财务指标切片，来自 Tushare `fina_indicator`。

同步日志写入 `SnapshotSyncLog`，前端可通过 `/api/snapshots/status` 展示同步状态。

### 6.3 因子注册与打分

核心文件：

- `myquant/factors/registry.py`
- `myquant/factors/buckets.py`
- `myquant/screening/pipeline.py`

因子按桶组织：

| 因子桶 | 含义 |
| --- | --- |
| `trend` | 技术趋势，例如均线多头、52 周高点距离、趋势斜率 |
| `momentum` | 动量，例如 20/60/120 日收益、行业相对强度 |
| `volume` | 成交量/成交额变化 |
| `valuation` | 估值，例如 PE、PB、股息率、行业估值分位 |
| `quality` | 财务质量，例如 ROE、营收增速 |
| `risk` | 波动、回撤、流动性风险 |
| `capital` | 资金面，当前多为高级权限预留 |
| `event` | 事件因子，默认展示预留、不参与打分 |

打分流程：

1. 根据价格缓存计算价格类因子。
2. 从股票池缓存读取估值、财务和行业字段。
3. 执行风险硬过滤。
4. 检查因子注册表中的可用性。
5. 按桶计算百分位分数，支持行业中性。
6. 对桶权重归一化，计算综合评分。
7. 输出入选原因、主要风险和缺失因子。

### 6.4 选股

旧接口：`POST /api/screen`

- 复用 `web_app.build_factor_screen`。
- 使用模板：稳健质量股、趋势质量股、低估值修复股、高成长强势股。
- 兼容旧前端筛选表和观察池流程。

新接口：`POST /api/screen/v2`

- 使用 `myquant.screening.pipeline.run_screen`。
- 以因子桶为核心输出 `bucket_meta`、`buckets`、缺失项和风险。
- 更适合后续做可解释的多因子工作台。

### 6.5 股票池

核心文件：

- `api/routers/pools.py`
- `myquant/pools/dao.py`
- `myquant/db/models.py`

模型：

- `Pool`：股票池主表。
- `PoolItem`：股票池成员，保存加入时快照、当前复评、用户标签、优先级、状态和备注。

默认池：

- 启动迁移会创建“短线观察池”。
- 同时创建“中线趋势池”“低估值价值池”“高股息防守池”等预设池。
- 旧 `watchlist.json` 会迁移到默认池，并保留备份。

### 6.6 择时

核心文件：

- `myquant/timing/rules.py`
- `myquant/timing/calculator.py`
- `myquant/timing/states.py`

输入是单标的价格特征，例如：

- 收盘价
- MA20/MA60/MA120
- 均线多头排列
- 20/60 日突破
- 60 日趋势斜率
- 52 周高点距离
- 60 日波动率
- 120 日最大回撤

输出择时状态：

- `breakout_confirmed`：突破确认
- `strong_watch`：强势观察
- `pullback_wait`：回踩等待
- `high_risk`：高位风险
- `trend_broken`：趋势破位
- `do_not_trade`：暂不交易

### 6.7 交易计划

核心文件：

- `api/routers/plans.py`
- `myquant/planning/generator.py`
- `myquant/planning/dao.py`
- `myquant/planning/stop_loss.py`
- `myquant/planning/position_sizing.py`
- `myquant/planning/fills.py`

计划生成流程：

1. 读取价格缓存并计算单标的价格特征。
2. 调用择时规则输出状态。
3. 根据状态映射 `action` 和 `confidence`。
4. 读取风控设置。
5. 计算入场区间、止损价、仓位、止盈层级。
6. 返回草稿计划，可选择保存到 SQLite。

执行追踪：

- `TradingPlan` 保存计划。
- `PlanFill` 记录实际成交。
- `summarize_plan` 汇总均价、剩余仓位、已实现盈亏等信息。

### 6.8 风控

核心文件：

- `api/routers/risk.py`
- `myquant/risk/settings.py`
- `myquant/risk/market_regime.py`
- `myquant/risk/portfolio_guard.py`

风控设置：

- 账户资金
- 单笔最大亏损比例
- 单标的最大仓位
- 行业最大暴露
- 强/中/弱市场仓位上限

组合检查：

- 汇总当前有效计划的标的和行业暴露。
- 根据市场状态映射总仓位上限。
- 对新增计划做硬拦或风险提示。

### 6.9 推荐关注

核心文件：

- `api/routers/recommend.py`
- `myquant/recommend/__init__.py`

推荐模块聚合股票池、观察池和市场范围标的，结合价格特征、择时状态和综合评分分组输出，作为前端“推荐关注”入口。

### 6.10 回测

固定股票池回测：

- 入口：`POST /api/backtest`
- 核心：`web_app.run_backtest_from_pool`
- 面向“当前选中/观察池标的在历史区间的表现”。
- 明确存在幸存者偏差和未来信息偏差，不应用作真实历史选股能力证明。

价格滚动回测：

- 入口：`POST /api/backtest/rolling/price`
- 核心：`myquant/backtest/rolling_price.py`
- 逻辑：在每个调仓日只使用当时及之前价格窗口打分，选 Top N 等权持有到下一期。
- 策略：20/60/120 日动量、60 日趋势斜率、60 日低波动。
- 可选择保存为 `BacktestRun` 和 `BacktestTrade`。

回测指标：

- 总收益
- 年化收益
- 最大回撤
- Sharpe
- 胜率
- 基准收益

### 6.11 场景模拟

核心文件：

- `api/routers/scenario.py`
- `myquant/scenario/simulator.py`

场景模拟基于当前计划、价格和用户输入的情景参数，评估组合在不同涨跌路径下的盈亏、风险暴露和计划敏感性。

### 6.12 个股详情与新闻

核心文件：`api/routers/stock.py`

能力：

- `/api/stock/{ticker}/kline`：返回单标的 K 线，优先 parquet 缓存，失败时用价格缓存合成。
- `/api/stock/{ticker}/summary`：聚合个股在股票池、计划、择时、因子中的摘要。
- `/api/stock/{ticker}/news`：通过 Google News RSS 拉取新闻，提取标签。

K 线设计降级顺序：

1. 使用 `outputs/cache/ohlcv/{ts_code}.parquet` 新鲜缓存。
2. 拉取 Tushare daily + adj_factor 并写入 parquet。
3. 外部数据失败时从 `price_cache.pkl` 合成 OHLCV，保证页面可用。

### 6.13 Agent 助手

核心文件：

- `api/routers/agent.py`
- `myquant/agents/service.py`
- `myquant/agents/prompt_builder.py`
- `myquant/agents/kimi_client.py`
- `myquant/agents/schemas.py`
- `frontend/src/app/components/AgentAssistantDrawer.tsx`

支持场景：

- 全局助手
- 个股诊断
- 筛选解释
- 回测复盘
- 新闻分析

后端约束：

- 可配置 `AGENT_ACCESS_TOKEN`。
- 按客户端做分钟级限流。
- Kimi/DeepSeek 通过 OpenAI-compatible chat completion 风格调用。
- 普通研究场景要求模型输出 JSON：`summary`、`key_points`、`risks`、`actions`。
- 新闻分析场景输出结构化纯文本。

前端能力：

- 多会话本地保存。
- Provider 切换。
- 本地临时覆盖 API key、base URL、model。
- 打字机式显示、停止生成、模板插值。

## 10. 核心业务流程

### 10.1 日常数据更新

```text
用户点击同步
  -> POST /api/tasks { action: sync_latest }
  -> FastAPI 创建后台线程
  -> 初始化 Tushare/TeaJoin client
  -> 确认最新可用交易日
  -> 读取 pool_cache 和 price_cache
  -> 缺失或落后则增量下载
  -> 保存 price_cache / pool_cache
  -> 前端轮询 /api/tasks/{task_id}
```

### 10.2 选股

```text
前端读取缓存诊断
  -> 若 can_screen=false 阻止选股
  -> 用户选择模板/行业/权重
  -> POST /api/screen 或 /api/screen/v2
  -> 后端读取 price_cache + pool_cache
  -> 风险过滤
  -> 因子打分
  -> 返回候选、剔除原因、权重和解释
  -> 用户加入观察池或股票池
```

### 10.3 从股票池到交易计划

```text
股票池/推荐/个股详情选择 ticker
  -> GET /api/timing/ticker/{ticker} 查看择时
  -> POST /api/plans/generate 生成计划
  -> 风控检查 evaluate_new_plan
  -> POST /api/plans 保存草稿或活动计划
  -> 可记录 PlanFill 做执行追踪
```

### 10.4 回测

```text
固定股票池回测:
  当前筛选/观察池 ticker
    -> POST /api/backtest
    -> price_cache 预检
    -> 多策略回测
    -> 指标、权益曲线、买卖点、建议

价格滚动回测:
  股票池或 ticker 列表
    -> POST /api/backtest/rolling/price
    -> 每期用历史窗口打分
    -> Top N 等权持有
    -> 指标、持仓、周期收益
    -> 可保存回测记录
```

### 10.5 Agent 诊断

```text
前端构造 scene + payload + user_input
  -> POST /api/agent/invoke
  -> 鉴权/限流
  -> prompt_builder 生成 system/user
  -> 调用 Kimi 或 DeepSeek
  -> 解析 JSON 或文本
  -> 前端以会话形式展示
```

## 11. 关键设计约束

### 11.1 数据质量优先

项目在多个入口进行数据预检：

- 缓存是否为空。
- 标的价格是否缺失。
- 本地缓存是否落后最新交易日。
- 关键基础面字段是否满足最低完整度。
- 因子是否可用。

前端会把状态区分为：

- 可实盘使用。
- 可研究使用。
- 禁止选股。

### 11.2 防未来函数

当前防未来函数设计分两层：

- 价格滚动回测只使用调仓日及之前的价格窗口打分。
- 财务快照模型保留 `ann_date`，为后续基础面滚动回测提供公告日约束。

仍需注意：

- 固定股票池回测使用当前股票池回看历史，天然存在幸存者偏差。
- 旧 `pool_cache.pkl` 是当前切片，不适合直接做历史逐期基础面回测。

### 11.3 本地优先

项目默认在本地运行：

- 数据缓存、数据库和输出文件都在 `outputs/`。
- 没有用户体系和多租户隔离。
- Agent API key 可通过环境变量或前端临时覆盖提供。

### 11.4 研究输出边界

系统应避免输出确定性买卖承诺：

- Agent prompt 明确要求只能做研究性分析。
- 交易计划是“草稿/检查清单”，不是自动下单。
- 回测结果需提示偏差和数据前提。

## 14. 当前技术债与风险

| 类型 | 现状 | 影响 | 建议 |
| --- | --- | --- | --- |
| 旧模块过大 | `web_app.py` 超过十万字节，混合 UI、数据、策略、缓存 | 修改风险高，复用边界不清 | 按数据服务、缓存服务、旧策略逐步拆出 |
| 双存储并存 | `watchlist.json` 与 SQLite 股票池并存 | 容易产生语义分叉 | 前端逐步全部切到 `/api/pools`，旧 watchlist 只读或废弃 |
| 无版本化迁移 | 当前使用 `create_all` | 字段变更后升级不可控 | 引入 Alembic 或轻量迁移版本表 |
| API 类型分散 | 前端类型散落在页面和组件 | 维护成本高 | 生成/维护共享 API schema 或前端 `types/api.ts` |
| 后台任务内存态 | 任务历史重启丢失 | 无法长期追踪数据更新 | 将任务记录写入 SQLite |
| 新闻源依赖 RSS | Google News RSS 可能不稳定 | 新闻卡片偶发失败 | 加缓存、降级和多源聚合 |
| Agent key 前端覆盖 | 前端可保存临时 key 到 localStorage | 有本地泄露风险 | 推荐生产只用后端环境变量 |
| 回测体系双轨 | 固定股票池回测和滚动价格回测逻辑分散 | 用户理解成本高 | 统一回测结果模型和说明口径 |

## 15. 演进路线

### 15.1 短期

- 把前端默认选股入口逐步迁移到 `/api/screen/v2`。
- 将旧观察池能力合并到 SQLite 股票池。
- 抽取前端 API client 和共享类型，减少 `page.tsx` 体积。
- 为核心路由补充 smoke 测试：健康检查、缓存摘要、股票池 CRUD、计划生成、滚动回测。

### 15.2 中期

- 引入版本化数据库迁移。
- 将 `web_app.py` 中的数据下载、缓存诊断、旧回测能力拆成 `myquant/data`、`myquant/backtest`、`myquant/legacy`。
- 让后台任务持久化到 SQLite，支持重启后查看历史。
- 建立统一的错误码和前端错误展示规范。
- 加强回测记录对参数、数据版本和缓存范围的记录。

### 15.3 长期

- 基于 `DailyBasicSnapshot` 和 `FinaSnapshot` 实现真正的历史基础面滚动选股回测。
- 接入更多事件因子和资金面因子，并通过因子注册表控制权限和降级。
- 建立数据版本/数据血缘，让每次筛选、计划、回测都能追溯输入数据。
- 如果要走向多人或远程部署，需要增加鉴权、权限、密钥管理和任务队列。

## 16. 开发约定建议

- 新业务状态优先落 SQLite，避免继续增加 JSON 文件状态。
- 新 API 优先放入 `api/routers/`，领域逻辑放入 `myquant/`，不要继续扩大 `api/main.py`。
- 与旧能力兼容时，可以短期调用 `web_app.py`，但新逻辑应逐步收敛到模块化包。
- 所有面向交易的输出都需要说明数据日期、缓存完整性、核心风险和适用边界。

### 17.6 新闻数据源

新闻接口（`/api/stock/{ticker}/news`）采用东方财富搜索 API，国内服务器可直连（~0.37s）：

```
https://search-api-web.eastmoney.com/search/jsonp?cb=&param=<URL编码的JSON>
```

响应为 JSONP 格式 `({"..."})` 而非纯 JSON，需在解析前去掉外层括号。Google News RSS 仅作最终兜底，在国内云服务器上可能超时。
- 回测功能新增时必须明确是否存在幸存者偏差、未来函数和费用/滑点假设。
- Agent 新场景应先定义 `scene`、输入 payload、输出 schema，再接入前端。
