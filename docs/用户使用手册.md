 # MyQuant 用户使用手册

更新时间：2026-05-31

本手册面向日常使用者，重点回答四个问题：

1. 怎么启动系统。
2. 每个页面是做什么的。
3. 一次完整研究流程怎么走。
4. 遇到常见问题怎么处理。

MyQuant 是本地量化研究和交易前检查工具，不是自动交易系统，也不保证收益。所有筛选、回测、计划和 AI 分析都应作为研究参考，最终决策需要你自行复核。

## 1. 快速开始

### 1.1 一键启动（推荐）

如果已经安装 `myquant-lan-service` Codex skill，可以直接运行：

```powershell
powershell -ExecutionPolicy Bypass -File C:\Users\64469\.codex\skills\myquant-lan-service\scripts\start-myquant-lan.ps1
```

脚本会同时启动后端和前端，并在终端输出本机访问地址、局域网访问地址和日志目录。

### 1.2 关闭服务

运行：

```powershell
powershell -ExecutionPolicy Bypass -File c:\Tarde\my_quant\scripts\stop-lan.ps1
```

关闭脚本会停止监听 `3000` 和 `8000` 端口的进程。

如果页面打不开、一直 404，或一键启动只提示 `Frontend already listening on 3000`，建议先完整关闭再启动：

```powershell
powershell -ExecutionPolicy Bypass -File c:\Tarde\my_quant\scripts\stop-lan.ps1
powershell -ExecutionPolicy Bypass -File C:\Users\64469\.codex\skills\myquant-lan-service\scripts\start-myquant-lan.ps1
```

排查时优先看日志：

- `outputs/logs/frontend-lan.out.log`
- `outputs/logs/frontend-lan.err.log`
- `outputs/logs/backend-lan.out.log`
- `outputs/logs/backend-lan.err.log`

### 1.3 手动启动后端

在项目根目录运行：

```powershell
c:/Tarde/my_quant/.venv/Scripts/python.exe -m uvicorn api.main:app --reload --host 0.0.0.0 --port 8000
```

启动成功后可访问：

- 本机 API 服务：http://127.0.0.1:8000
- 局域网 API 文档：http://本机局域网IP:8000/docs

### 1.4 手动启动前端

在另一个终端运行：

```powershell
cd c:/Tarde/my_quant/frontend
npm install
npm run dev:lan
```

浏览器打开：

- 本机：http://localhost:3000
- 同一局域网其他设备：http://本机局域网IP:3000

如果 3000 端口被占用，Next.js 会自动切换到 3001 或其他端口，以终端输出的 `Local` 地址为准。

### 1.5 旧版 Streamlit

旧版界面仍可作为对照使用：

```powershell
c:/Tarde/my_quant/.venv/Scripts/python.exe -m streamlit run c:/Tarde/my_quant/web_app.py --server.headless true --server.address 0.0.0.0 --server.port 8501
```

浏览器打开：

- 本机：http://localhost:8501
- 同一局域网其他设备：http://本机局域网IP:8501

日常建议优先使用新版前端。

## 2. 第一次使用前准备

### 2.1 Tushare Token

以下操作需要 Tushare Token：

- 同步到最新交易日。
- 修复行情价格缓存。
- 刷新基础面字段。
- 全量重建价格缓存。
- 拉取个股 K 线时，如果本地没有可用缓存，也可能需要 Token。

如果本地缓存已经完整，筛选、观察、固定股票池回测通常不需要再次提供 Token。

### 2.2 Agent 配置

AI 助手支持 Kimi 和 DeepSeek。推荐在后端环境变量中配置：

| 配置项 | 说明 |
| --- | --- |
| `AGENT_DEFAULT_PROVIDER` | 默认模型供应商，`kimi` 或 `deepseek` |
| `KIMI_API_KEY` | Kimi API Key |
| `KIMI_BASE_URL` | Kimi 地址，默认 `https://api.moonshot.cn/v1` |
| `KIMI_MODEL` | Kimi 模型 |
| `DEEPSEEK_API_KEY` | DeepSeek API Key |
| `DEEPSEEK_BASE_URL` | DeepSeek 地址 |
| `DEEPSEEK_MODEL` | DeepSeek 模型 |
| `AGENT_ACCESS_TOKEN` | 可选访问口令 |

前端 AI 助手抽屉中也可以临时填写 key、base URL 和 model，但这些配置只适合本地临时使用。

### 2.3 本地缓存位置

常用缓存文件：

| 文件 | 用途 |
| --- | --- |
| `outputs/cache/price_cache.pkl` | 价格缓存 |
| `outputs/cache/pool_cache.pkl` | 股票池基础数据缓存 |
| `outputs/cache/watchlist.json` | 旧观察池 |
| `outputs/cache/myquant.db` | 新版股票池、计划、风控、回测记录 |
| `outputs/cache/ohlcv/*.parquet` | 个股 K 线缓存 |

## 3. 推荐使用流程

### 3.1 日常研究流程

建议每天按这个顺序使用：

1. 打开“数据概览”，确认数据状态。
2. 进入“数据更新”，执行推荐操作。
3. 打开“推荐关注”或“筛选择股”，查看候选标的。
4. 把感兴趣的标的加入股票池。
5. 查看个股详情和择时状态。
6. 生成交易计划。
7. 用“风险控制”和“场景模拟”复核仓位风险。
8. 用“策略回测”验证思路，不把回测当收益承诺。

### 3.2 新手最短流程

如果你只是想快速跑通：

1. 启动前后端。
2. 打开“数据更新”，执行“同步到最新”或页面推荐动作。
3. 打开“推荐关注”，挑一只看得懂的股票。
4. 点“Agent解读”，让助手解释原因和风险。
5. 点“生成计划”，进入“交易计划”检查入场、止损和仓位。

### 3.3 交易前检查流程

真正准备下单前，至少检查：

- 数据是否为“可实盘使用”或至少“可研究使用”。
- 个股是否处于可接受的择时状态。
- 是否有止损价。
- 单笔亏损是否在可承受范围内。
- 单标的仓位、行业暴露、总仓位是否超过风控设置。
- 是否临近财报、公告、停牌、涨跌停等事件风险。
- 回测是否存在明显过拟合、幸存者偏差或样本太短。

## 4. 页面使用说明

## 4.1 数据概览

数据概览用于判断当前数据能不能用。

重点看：

| 指标 | 怎么理解 |
| --- | --- |
| 数据状态 | “可实盘使用”“可研究使用”“禁止选股” |
| 缓存日期范围 | 本地价格数据覆盖到哪一天 |
| 最新交易日 | 外部交易日历确认的最新开放交易日 |
| 缺失/落后标的 | 股票池中哪些标的没有价格或日期落后 |
| 基础面完整度 | ROE、GROWTH、PE、PB、成交额等是否够用 |
| 推荐操作 | 系统建议下一步执行什么修复或同步 |

状态解释：

| 状态 | 含义 | 建议 |
| --- | --- | --- |
| 可实盘使用 | 数据覆盖最新交易日，关键字段可用 | 可作为交易前研究输入 |
| 可研究使用 | 数据基本完整，但可能未覆盖最新交易日 | 适合复盘和观察，不建议直接下单 |
| 禁止选股 | 行情、基础面或因子存在明显问题 | 先去数据更新页修复 |

## 4.2 数据更新

数据更新用于维护本地缓存。

常用动作：

| 动作 | 适用场景 | 风险 |
| --- | --- | --- |
| 同步到最新 | 日常使用首选 | 低 |
| 修复行情价格缓存 | 有缺失标的或落后标的 | 中 |
| 刷新基础面字段 | ROE/GROWTH/PE/PB/成交额缺失较多 | 中 |
| 全量重建 | 缓存严重异常，普通修复无效 | 高 |

推荐做法：

- 优先点页面提示的“推荐操作”。
- 下载并发数先用默认值，稳定后再调高。
- 如果接口频繁失败，降低并发或稍后重试。
- “全量重建”会耗时较长，只在普通修复无效时使用。

任务执行时：

- 顶部任务条会显示进度。
- 可以在任务未完成时取消，但取消通常要等当前批次结束。
- 任务历史只保存在当前后端进程中，重启后不会保留。

## 4.3 推荐关注

推荐关注会把系统认为值得观察的标的按状态分组展示。

常见分组：

| 分组 | 含义 | 操作建议 |
| --- | --- | --- |
| 突破强势 | 价格突破近期高点，趋势偏强 | 关注回踩和放量确认 |
| 强势观察 | 趋势较好，但入场点未必舒服 | 加入股票池继续跟踪 |
| 回踩布局 | 强势股回调到均线附近 | 等待企稳，不追高 |
| 防御止损 | 趋势破坏或风险偏高 | 谨慎新开仓 |
| 暂不交易 | 信号不清或数据不足 | 先观察 |

常用操作：

- 查看推荐理由和风险标签。
- 打开个股详情。
- 加入股票池。
- 生成交易计划。
- 点“Agent解读”获取自然语言解释。

## 4.4 筛选择股

筛选择股适合按你的风格主动找股票。

基本步骤：

1. 确认数据状态允许选股。
2. 选择筛选模板或因子权重。
3. 可选行业范围。
4. 设置候选数量。
5. 执行筛选。
6. 查看候选表、剔除原因、因子分和风险提示。
7. 把满意标的加入观察池或股票池。

常见模板：

| 模板 | 偏好 |
| --- | --- |
| 稳健质量股 | 财务质量、风险控制更重要 |
| 趋势质量股 | 趋势和质量兼顾 |
| 低估值修复股 | 估值偏低、等待修复 |
| 高成长强势股 | 成长和动量更强，但波动可能更大 |

重要开关：

| 开关 | 说明 |
| --- | --- |
| 行业中性 | 行业内比较，避免热门行业天然占优 |
| 允许不完整因子 | 数据缺失时仍继续筛选，结果可信度下降 |
| 行业过滤 | 只在指定行业中筛选 |

使用建议：

- 不确定时先用“稳健质量股”。
- 如果候选太少，放宽风险过滤或扩大行业范围。
- 如果候选太多，提高质量、风险控制或趋势权重。
- 不要只看综合评分，至少同时看入选原因和主要风险。

## 4.5 股票池

股票池用于长期跟踪标的，不只是临时观察。

默认包含：

- 短线观察池。
- 中线趋势池。
- 低估值价值池。
- 高股息防守池。

你可以：

- 新建股票池。
- 添加或批量添加股票。
- 编辑股票池名称、类型和说明。
- 移出股票。
- 清空股票池。
- 给股票加备注、标签、优先级和状态。
- 对池内股票做当前复评。

推荐用法：

- 不同风格分不同池，不要全部堆在一个列表里。
- 入池时记录原因，后续复盘才知道当时为什么看好。
- 定期复评，分数明显下降或状态变坏时及时处理。

## 4.6 个股详情

个股详情用于看单只股票的综合信息。

通常包含：

- K 线图。
- 当前择时状态。
- 所属股票池。
- 关联交易计划。
- 价格特征和因子指标。
- 新闻资讯。
- Agent 诊断入口。

K 线来源优先级：

1. 本地 OHLCV parquet 缓存。
2. Tushare 拉取并写入缓存。
3. 外部拉取失败时，从价格缓存合成简化 K 线。

注意：

- 合成 K 线没有真实成交量和真实开高低数据，只适合临时查看趋势。
- 新闻来自 RSS，可能有延迟或缺漏，重要信息仍需人工核实。

## 4.7 因子中心

因子中心展示当前系统支持的因子及可用性。

你可以看到：

- 因子名称。
- 所属因子桶。
- 数据来源。
- 刷新频率。
- 是否参与打分。
- 是否当前可用。
- 不可用原因。

常见不可用原因：

- 价格缓存为空。
- 股票池缺少行业字段。
- 股票池缺少 PE/PB/ROE/GROWTH 等字段。
- 需要高级权限的数据源未接入。
- 事件类因子暂未稳定接入。

## 4.8 风险控制

风险控制用于设置账户级约束，并检查组合暴露。

常见设置：

| 设置 | 说明 |
| --- | --- |
| 账户资金 | 用于仓位计算 |
| 单笔最大亏损比例 | 单只股票触发止损时最多亏多少账户资金 |
| 单标的最大仓位 | 单只股票最高占账户比例 |
| 行业最大暴露 | 单个行业最高占账户比例 |
| 强/中/弱市场仓位上限 | 不同市场环境下的总仓位限制 |

建议：

- 新手把单笔最大亏损控制在较低比例。
- 不要把多个相似行业或高度相关股票当作分散。
- 交易计划保存前，先看风控是否有硬拦或警告。

## 4.9 交易计划

交易计划把“看好一只股票”转成可检查的执行草稿。

计划字段：

| 字段 | 含义 |
| --- | --- |
| action | 买入、加仓、持有、减仓、退出等动作 |
| trading_state | 当前择时状态 |
| confidence | 高、中、低置信度 |
| entry_zone | 入场区间 |
| stop_loss | 止损价 |
| take_profits | 分批止盈价 |
| position_pct | 建议仓位比例 |
| position_shares | 建议股数 |
| reasons | 计划理由 |
| risks | 风险提示 |
| valid_until | 计划有效期 |
| status | 草稿、活动、已执行、取消、过期 |

使用步骤：

1. 从推荐关注、股票池或个股详情生成计划。
2. 检查入场区间是否合理。
3. 检查止损是否能接受。
4. 检查仓位是否符合账户承受力。
5. 补充备注。
6. 保存为草稿或活动计划。
7. 如果真实成交，记录成交。

底线要求：

- 没有止损的计划不要执行。
- 不知道为什么买的计划不要执行。
- 超过风控限制的计划不要硬上。

## 4.10 成交记录

成交记录用于追踪计划执行情况。

你可以记录：

- 买入或卖出。
- 成交日期。
- 成交价格。
- 数量。
- 费用。
- 备注。

系统会根据成交记录汇总：

- 当前剩余数量。
- 平均成本。
- 已实现盈亏。
- 执行进度。

## 4.11 场景模拟

场景模拟用于回答“如果市场这样走，我的组合会怎样”。

常见用途：

- 看大盘下跌时组合可能亏多少。
- 看某个行业回撤时是否超出承受范围。
- 看单只计划对组合影响有多大。
- 检查止损、止盈和仓位是否太激进。

使用建议：

- 模拟结果不是预测，只是压力测试。
- 多测几个悲观场景，比只看乐观场景更有价值。

## 4.12 策略回测

系统有两类回测。

### 固定股票池回测

入口通常是策略回测页的旧版多策略回测。

特点：

- 使用当前选择的股票池或观察池。
- 在历史区间内回看这批股票表现。
- 会返回策略对比、组合指标、权益曲线、买卖点和建议。

重要限制：

- 存在幸存者偏差。
- 存在未来信息偏差。
- 只能说明“现在这组股票过去表现如何”，不能证明当时能选出它们。

### 价格滚动回测

入口是滚动回测面板。

特点：

- 每个调仓日只使用当时之前的价格窗口。
- 根据动量、趋势斜率、低波动等策略打分。
- 选择 Top N 等权持有到下一期。
- 可保存回测记录。

常见策略：

| 策略 | 说明 |
| --- | --- |
| 20 日动量 | 近期强势，换手更快 |
| 60 日动量 | 中短期趋势，较均衡 |
| 120 日动量 | 中期趋势，换手较慢 |
| 60 日趋势斜率 | 找相对平滑上行的标的 |
| 低波动 60 日 | 偏防守 |

看回测时重点关注：

- 最大回撤，而不只是收益。
- 是否跑赢基准。
- 样本区间是否足够长。
- 调仓频率是否现实。
- 交易费用和滑点是否合理。
- 是否只在某一小段市场中特别有效。

## 4.13 回测记录

保存后的滚动回测可以在回测记录中查看。

通常包含：

- 策略名称。
- 调仓频率。
- 回测区间。
- Top N。
- 收益和回撤。
- 权益曲线。
- 持仓和调仓明细。

建议：

- 给重要回测加标签。
- 修改参数后保存新记录，便于横向比较。
- 不要只保留表现最好的那一次，否则容易过拟合。

## 4.14 基础面快照

基础面快照用于同步更适合历史研究的数据切片。

包含：

- 每日估值/市值/换手等数据。
- 财务指标和公告日。
- 同步日志。

用途：

- 支撑后续更可信的历史基础面回测。
- 避免直接用当前财务数据回看历史造成未来函数。

日常如果只做普通筛选和观察，可以先不频繁操作这一页。

## 4.15 AI 助手

入口：

- 页面右上角“AI 助手”。
- 推荐关注中的“Agent解读”。
- 筛选结果、观察池、个股详情、回测复盘等功能入口。

适合问：

- 这只股票为什么被推荐。
- 这次筛选结果有什么风格偏向。
- 这个回测有什么问题。
- 新闻对基本面和短期情绪有什么影响。
- 当前页面下一步该怎么操作。

不适合问：

- 明天一定涨不涨。
- 直接告诉我买多少。
- 保证收益的操作。

推荐提问：

```text
请用保守投资者能理解的话解释这只股票当前状态，重点说入场条件、失效条件和最大风险。
```

```text
请复盘这次回测，指出收益来源、最大回撤风险、样本偏差和下一步改进实验。
```

```text
我只想低风险观察，请帮我把这个计划改成更保守的检查清单。
```

注意：

- AI 助手只基于传入上下文分析，不能替代实时行情和公告核查。
- 如果后端配置了访问口令，前端需要输入口令。
- 如果没有配置 API key，Agent 健康检查会提示不可用。

## 5. 常见工作流

### 5.1 从零生成一份交易计划

1. 数据概览确认数据可用。
2. 数据更新执行推荐操作。
3. 推荐关注挑选标的。
4. 打开个股详情，查看 K 线和择时状态。
5. 点 Agent 解读，确认主要理由和风险。
6. 生成交易计划。
7. 在交易计划页检查入场、止损、止盈、仓位。
8. 风险控制页检查组合暴露。
9. 场景模拟页测试悲观情景。
10. 人工复核公告、财报、涨跌停和流动性。

### 5.2 做一次主动筛选

1. 打开筛选择股。
2. 选择模板。
3. 设置行业范围。
4. 调整因子权重。
5. 执行筛选。
6. 查看剔除摘要。
7. 对前几名逐个打开详情。
8. 加入合适的股票池。
9. 后续在股票池中复评。

### 5.3 做一次策略复盘

1. 选择股票池或 ticker 列表。
2. 打开滚动回测。
3. 选择策略、调仓频率和 Top N。
4. 设置回测区间。
5. 运行回测。
6. 查看收益、回撤、胜率和基准对比。
7. 保存回测记录。
8. 用 AI 助手复盘缺陷。

### 5.4 维护股票池

1. 每周打开股票池。
2. 对重点池执行复评。
3. 移除趋势破坏或理由失效的股票。
4. 给仍需观察的股票补充备注。
5. 对高优先级股票生成或更新交易计划。

## 6. 常见问题

### 6.1 后端打不开

检查：

- 是否在项目根目录运行。
- 虚拟环境路径是否存在。
- `requirements-api.txt` 是否已安装。
- 8000 端口是否被占用。

可访问 http://127.0.0.1:8000/docs 判断后端是否启动成功；同一局域网其他设备访问 http://本机局域网IP:8000/docs。

### 6.2 前端打不开

检查：

- 是否进入 `frontend` 目录。
- 是否运行过 `npm install`。
- 终端输出的实际端口是否不是 3000。
- 后端是否也已启动。

### 6.3 页面提示无法连接 API

检查：

- FastAPI 是否使用 `--host 0.0.0.0 --port 8000` 启动。
- 前端 `NEXT_PUBLIC_API_BASE_URL` 是否指向正确地址。
- 浏览器控制台是否有跨域或网络错误。

### 6.4 同一局域网其他设备打不开

检查：

- 后端是否用 `--host 0.0.0.0` 启动。
- 前端是否用 `npm run dev:lan` 启动。
- 访问地址是否是 `http://本机局域网IP:3000`，不是 `localhost`。
- Windows 防火墙是否允许入站 TCP 端口 `3000` 和 `8000`。
- 两台设备是否连接在同一个局域网，且路由器没有开启客户端隔离。

### 6.5 数据状态是“禁止选股”

常见原因：

- 价格缓存为空。
- 股票池价格缺失。
- 缓存落后太多。
- 基础面字段缺失。
- 因子不可用。

处理顺序：

1. 先执行“同步到最新”。
2. 仍有缺失时执行“修复行情价格缓存”。
3. 基础面缺失时执行“刷新基础面字段”。
4. 仍异常再考虑“全量重建”。

### 6.5 筛选结果为空

可能原因：

- 行业过滤太窄。
- 风险过滤太严格。
- `top_n` 太小。
- 缓存数据不足。
- 因子数据缺失。

处理：

- 放宽行业范围。
- 降低硬过滤条件。
- 允许更多候选数量。
- 回到数据更新页修复数据。

### 6.6 回测被阻止

原因通常是所选股票在回测区间内价格不完整。

建议：

- 先修复行情缓存。
- 缩短或调整回测区间。
- 换一组有完整价格的股票。
- 只有在明确知道风险时，才允许不完整数据继续回测。

### 6.7 Agent 不可用

检查：

- 是否配置了 Kimi 或 DeepSeek API key。
- Provider 是否选择正确。
- base URL 和 model 是否正确。
- 如果设置了 `AGENT_ACCESS_TOKEN`，前端口令是否正确。
- 是否触发限流。

### 6.8 K 线没有真实成交量

如果 Tushare 拉取失败，系统可能从价格缓存合成 K 线。合成 K 线主要用于临时查看趋势，不代表真实开高低和成交量。

### 6.9 回测很好看，是否可以直接照做

不建议。

你至少要确认：

- 是否存在未来信息。
- 是否存在幸存者偏差。
- 是否覆盖不同市场阶段。
- 是否考虑费用、滑点、停牌、涨跌停和流动性。
- 最大回撤是否能承受。

## 8. 安全和风险提示

请牢记：

- 本工具不自动下单。
- 本工具不保证收益。
- AI 助手不是投资顾问。
- 回测不是未来收益承诺。
- 数据源可能延迟、缺失或出错。
- 任何交易前都应人工复核公告、财报、涨跌停、流动性和仓位风险。

建议：

- 先用小仓位验证流程。
- 每笔交易都写清楚理由和失效条件。
- 亏损到止损条件时先执行纪律，再复盘。
- 不要因为模型或回测漂亮就忽略风险。
